# Mind Palace Protocol v0.9.3

## Outcome

This release makes common memory a latest-only pointer to an immutable protocol
release. Protocol resources remain in Git and are fetched and digest-verified
when needed.

## Changes

- Replace copied Core Bundle and attachment projection with one Source Pointer.
- Verify the Release Index and required core resources before pointer activation.
- Keep per-resource proof in the read-only staging plan, not common memory.
- Remove provider-backed protocol caches and their budgets.
- Add bounded, resumable cleanup planning for superseded protocol records.
- Preserve the installation root, client receipts, user documents, and only
  explicitly exempted legacy guidance during cleanup.

## Compatibility

Document and migration semantics remain compatible with `v0.9.2`. The
common-memory representation changes incompatibly during the experimental
`0.y.z` series. Legacy component, compact-bundle, and attachment records remain
recognizable until post-activation cleanup removes them.

## Rollback

Recreate the prior Source Pointer from its immutable Git tag and Release Index,
verify it, and activate it through the normal approval path. Do not retain old
protocol projections solely for rollback.
