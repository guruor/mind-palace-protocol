# Mind Palace Protocol v0.5.0

## Outcome

This release replaces the new-release file-by-file projection model with a
compact Release Index and Core Bundle. It supports immutable on-demand resource
lookup without changing active common memory.

## Changes

- Add a generated Release Index with path, raw SHA-256 digest, byte count,
  resource class, cache policy, and purpose.
- Define six small core resources for normal Product Engineering work.
- Keep document-type contracts, templates, schemas, and detailed bindings
  available on demand.
- Keep setup and migration material maintenance-only.
- Exclude scripts, tests, fixtures, CI, and release tooling from distribution.
- Add a short Notion runtime binding.
- Allow retained `v0.1.x` component records while requiring compact
  distribution for new releases.
- Update the installation state machine to verify and repair core resources.
- Detect a changed Release Index as an identity conflict.

## Compatibility

Legacy common-memory releases remain valid for rollback. New compact releases
use `release_index` and `core_bundle` instead of generated `components`. Client
adapters and user documents are unchanged. Common memory stays on active
`v0.1.0` until a later real-vendor dry run is reviewed and approved.

## Rollback

No external state is written by publishing this release. A future deployment
retains the active legacy release and switches the active pointer only after the
compact release validates.
