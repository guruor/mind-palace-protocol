# Mind Palace Protocol v0.8.0

## Outcome

This release makes user-requested document migration a portable, repeatable
protocol workflow. A request to migrate selected or all authorized documents
produces a read-only inventory and reviewed plan before any document write.

## Changes

- Define narrow `selected` and `all-authorized` scope semantics.
- Separate requested sources, dependency reads, exclusions, and write scope.
- Require source classification, target mapping, stable-ID collision checks,
  change tokens, risk analysis, provider budget, snapshots, and rollback.
- Add a migration-plan schema with an explicit pending approval boundary.
- Bind approval to the plan scope digest and source revisions.
- Require pre-write re-reads, serialized idempotent batches, conflict
  preservation, validation, and re-planning on material drift.
- Add valid and invalid migration-plan fixtures to release validation.

## Compatibility

The workflow is additive. Product Engineering, existing bindings, version-neutral
client adapters, common-memory state, and user documents remain unchanged.
Common memory remains on active `v0.7.0` pending a separate deployment plan.

## Rollback

Revert clients to the previous active protocol release. No document migration or
common-memory update is performed by publishing this source release.
