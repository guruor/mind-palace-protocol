# Mind Palace Protocol v0.2.0

## Outcome

This release records the architecture baseline for an AI-first shared knowledge
system. It changes design direction and vocabulary without changing the current
common-memory installation format or migrating user knowledge.

## Changes

- Define the protocol as collaboration and document-type guidance, not an index
  of individual user documents.
- Define Knowledge Methods and Storage Bindings as declarative, versioned
  extension points.
- Define portable document-type contracts, logical locations, relationships,
  retrieval, writes, lifecycle, and migration as method responsibilities.
- Keep vendor hierarchy, search mechanics, visual presentation, and capability
  limits in Storage Bindings.
- Define a future compact Core Bundle, immutable Release Index, on-demand remote
  resources, and bounded verified cache.
- Classify resources as `core`, `on-demand`, `maintenance`, or `development`.
- Require provider-aware read-only planning before future common-memory writes.
- Defer executable plugins, automatic package installation, central registries,
  and user-knowledge migration.

## Compatibility

The current schemas, `product-engineering` methodology, Notion binding, client
adapters, and installation behavior remain compatible. This release does not
change common memory. The active common-memory release remains `v0.1.0`, and the
blocked `v0.1.2` records remain unchanged.

## Rollback

No external state is written by this release. Clients continue to use the
active `v0.1.0` common-memory installation until a later compact-distribution
release is explicitly staged, verified, and approved.
