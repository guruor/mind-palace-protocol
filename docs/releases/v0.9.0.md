# Mind Palace Protocol v0.9.0

## Outcome

This release makes document migration deliberately incremental and resilient to
provider rate limits. It also defines when AI may convert document structure or
wording without silently changing meaning.

## Changes

- Default to incremental execution with bounded documents per run.
- Reserve request headroom for verification and rollback.
- Checkpoint completed source IDs after every document by default.
- Pause on rate limiting, honor provider retry timing, and resume only pending
  work after re-reading source and target state.
- Keep validated earlier batches when a later batch pauses.
- Classify AI conversion as preserve, structural, meaning-preserving, material,
  or unknown with explicit semantic impact.
- Permit structural and low-impact meaning-preserving conversion only within an
  approved plan and reviewed preview.
- Require explicit acknowledgement for material or unknown semantic changes.
- Validate progress partitions, bounded next batches, rate-limit resume state,
  and approval invalidation when migration actions change.

## Compatibility

This release extends the `v0.8.0` migration contract. No document, client
receipt, legacy record, or common-memory release is modified by source
publication. Common memory remains on active `v0.7.0` pending a separate plan.

## Rollback

Use the prior active protocol release. Incremental document migrations retain
per-document checkpoints and snapshots so rollback can be limited to the
affected approved scope.
