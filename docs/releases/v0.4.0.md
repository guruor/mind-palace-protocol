# Mind Palace Protocol v0.4.0

## Outcome

This release converts Product Engineering into the first complete built-in
Knowledge Method. It defines document types, not individual project documents,
and does not migrate user knowledge.

## Changes

- Add a built-in Product Engineering package manifest.
- Add one portable contract for each of the ten supported document types.
- Define logical locations, metadata, ownership, lifecycle, required sections,
  relationships, retrieval, writes, and migration for every type.
- Validate that the package catalog and document-type files match.
- Validate that every contract's required headings exist in its template.
- Add a Product Engineering migration guide.
- Allow a built-in extension package to inherit identity and integrity from its
  enclosing immutable protocol release.
- Update Product Engineering to method version `0.2.0`.

## Compatibility

The document kinds and portable artifact envelope remain compatible. Existing
Product Engineering documents are not changed automatically. Their earlier
method version can be mapped through an explicit future migration. Client and
common-memory installation behavior remains unchanged, and common memory stays
on active `v0.1.0`.

## Rollback

No external state is written by this release. Existing documents continue to
use their recorded method version until a separate migration is reviewed and
approved.
