# Mind Palace Protocol v0.1.2

## Compatibility

This release clarifies lifecycle ownership without changing artifact schemas or
the `product-engineering` methodology. Existing version-neutral hosted-chat and
Agent Skill bootstraps remain compatible and do not need reinstallation.

## Changes

- Define ChatGPT, Claude, OpenCode, and Agent Skill setup as a one-time,
  version-neutral discovery operation.
- Make the common-memory installation the sole owner of the active protocol
  release.
- Require an explicit user request before installing, updating, repairing,
  rolling back, or otherwise changing the shared protocol.
- Require every Mind Palace task to resolve and follow the active common-memory
  release without searching for a newer release.
- Treat client receipts as latest-resolution evidence rather than active release
  pointers.
- Refresh a receipt before protocol-governed writes or explicit validation, not
  as a side effect of ordinary reads.
- Separate protocol release updates from legacy document/artifact migrations.
- Require cross-client handoff validation only when work crosses clients or
  cross-client portability is claimed.

## Upgrade And Rollback

Stage and validate `v0.1.2` through the explicit common-memory update flow, then
switch the shared active pointer while retaining the prior release for rollback.
Do not edit existing Custom Instructions, Skills, `AGENTS.md`, or client adapter
configuration for this protocol update. Clients resolve the new active release
on their next Mind Palace task. They refresh their existing receipts before a
protocol-governed write or when explicitly asked to record validation evidence.
