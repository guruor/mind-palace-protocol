# Mind Palace Protocol v0.7.0

## Outcome

This release supports approved declarative Knowledge Methods and Storage
Bindings from immutable external sources. It completes the source-level core
protocol and extension foundation without changing common memory or user
knowledge.

## Changes

- Add an approved extension-source schema and instance configuration support.
- Resolve external manifests from immutable HTTPS references with a 200 KiB
  limit, no redirects, and private-network rejection.
- Verify manifest digest, package identity, type, version, source revision, and
  protocol compatibility before use.
- Require explicit source approval.
- Validate declared package dependencies and required binding capabilities.
- Reject duplicate document-type ownership.
- Reject non-declarative package resources.
- Add a complete example external Research Method with one document type.
- Add an example external plain-files Storage Binding.
- Add deterministic success, digest-conflict, incompatibility, ownership
  conflict, and capability checks.

## Compatibility

Built-in Product Engineering, Notion, Markdown/Git, client adapters, and legacy
common-memory releases remain compatible. External package selection is
additive and explicit. Common memory remains on active `v0.1.0` until the real
`v0.7.0` deployment plan is reviewed and approved.

## Rollback

Remove the selected extension reference and return to the previous valid method
or binding. Package resolution writes no user knowledge and publishing this
release performs no common-memory mutation.
