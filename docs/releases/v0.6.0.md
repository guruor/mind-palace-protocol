# Mind Palace Protocol v0.6.0

## Outcome

This release adds a read-only, provider-aware write planner and deterministic
cache and resume safety checks. The planner has no vendor client and cannot
perform common-memory writes.

## Changes

- Add conservative Notion operation, cache, and retry budgets.
- Add schemas for provider budgets and common-memory write plans.
- Calculate staging records, text bytes, attachments, requests, batches, and
  rollback writes before execution.
- Model one compact release record containing the Release Index and Core Bundle.
- Reject over-budget plans before calling a writer.
- Admit only eligible, size-bounded immutable resources to cache.
- Reuse existing cache entries without a write.
- Preserve completed stable IDs on a simulated rate limit and resume only
  missing writes.
- Keep cache failure separate from read and proposal success.

## Compatibility

This release does not contact Notion, stage a release, activate common memory,
or migrate user knowledge. Existing client adapters remain compatible. Common
memory remains on active `v0.1.0`.

## Rollback

No external state is written by publishing or running the planner. Future
vendor execution must use a separately reviewed plan and retain `v0.1.0` until
the compact release is verified and explicitly activated.
