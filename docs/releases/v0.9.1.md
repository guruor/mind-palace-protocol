# Mind Palace Protocol v0.9.1

## Outcome

This release makes compact common-memory staging deterministic and
proof-carrying. It closes the manual payload-assembly gap found while staging
`v0.9.0`.

## Changes

- Build the Release Index and six-resource Core Bundle directly from source.
- Preserve exact UTF-8 bytes instead of permitting manual reformatting.
- Record payload, Release Index, and per-resource bytes and digests.
- Bind common-memory plans to the generated payload proof.
- Reject changed, missing, reordered, duplicated, or normalized sections.
- Require read-after-write extraction and verification before activation.
- Keep a failed candidate blocked without changing the active pointer.

## Compatibility

The protocol and Product Engineering document semantics remain compatible with
`v0.9.0`. The change hardens distribution and verification. Common memory
remains on active `v0.7.0` until a separate digest-bound staging and activation
process succeeds.

## Rollback

Mark only the candidate release blocked and leave the installation active
pointer unchanged. Retain the failed record and proof as audit evidence.
